# qa-service

A small authenticated HTTP service around the `redevops-qa` command, for running the product as a long-lived process in a container. Standard library only.

It adds no test logic. Every run, report and verification is the `redevops-qa` command started as a child process, and the service keeps what that command wrote. It cannot be pointed at an
external application: the plans it starts are the ones that ship with the runner (`demo`, `browser`, `robot`, `robot-not-enforced`), and they run against the fixture app, exactly as the
command line does (the external target is audit item P2-1, still design work). There is no web interface; the one HTML page is the static report of `redevops-qa report --format html`,
served as that command renders it.

## Authentication

The service has no default credential. It does not start (exit status 78, a message that never repeats the value) unless `QA_SERVICE_TOKEN_FILE` (a file holding the token, for example a mounted
secret) or `QA_SERVICE_TOKEN` is set to a token of at least 32 characters from `A-Z a-z 0-9 . _ ~ + / = -` with at least 8 distinct characters that does not look like a placeholder. Generate one
with `openssl rand -hex 32`. Every path except `/healthz` and `/readyz` needs `Authorization: Bearer <token>`; the comparison is constant-time, a failed attempt waits a quarter of a second
before it is answered, and the token is never logged or passed to the command the service starts (the child gets `PATH`, `HOME`, `LANG`, `TMPDIR`, `REDEVOPS_QA_PINS` and
`PLAYWRIGHT_BROWSERS_PATH` and nothing else).

## Endpoints

| Method and path | What it does |
|---|---|
| `GET /healthz` | the process is up (no authentication, no information) |
| `GET /readyz` | the data directory is writable and the command is present: 200 `ready` or 503 `not_ready` with the names of the failing checks |
| `GET /v1/info` | version, machine, the plans and whether each can start in this installation (a lane whose Python package is missing is `available: false` with the reason) |
| `POST /v1/runs` | body `{"plan": "demo\|browser\|robot\|robot-not-enforced", "defect": "none\|discount\|settings"}` (both optional, default `demo` and `none`; any other field is refused): 202 with the run record; 409 while another run is going; 422 if the plan cannot start here |
| `GET /v1/runs`, `GET /v1/runs/<id>` | the newest runs; one run: state, exit code, outcome (`VERIFIED`, `FAILED`, `REFUSED`, `NOT_COMPLETED`, `INCONCLUSIVE`, `EVIDENCE_REJECTED`, `RUNNER_ERROR`, from the runner's exit-status table) |
| `GET /v1/runs/<id>/output` | what the command printed |
| `GET /v1/runs/<id>/report?format=text\|json\|html` | `redevops-qa report` of the evidence bundle (it re-verifies the bundle first and shows nothing of a bundle that does not verify) |
| `GET /v1/runs/<id>/verify` | `redevops-qa verify --json` of the evidence bundle |
| `GET /v1/runs/<id>/bundle.tar` | the evidence bundle, for `redevops-qa verify` on another machine |
| `DELETE /v1/runs/<id>` | remove a run that is not going |

One run at a time; a run is killed after `QA_SERVICE_RUN_TIMEOUT` seconds (default 1800). A run that was going when the service stopped is marked `interrupted` at the next start.
Requests are limited to a 4 KiB JSON body and a 30 second socket timeout. Run ids are generated by the service (`rYYYYMMDDTHHMMSSZ-xxxxxx`); no request names a path.

## Configuration

| Variable | Default | Meaning |
|---|---|---|
| `QA_SERVICE_TOKEN_FILE` / `QA_SERVICE_TOKEN` | none (required, exactly one) | the bearer token |
| `QA_SERVICE_BIND` | `127.0.0.1` | an IP address to listen on |
| `QA_SERVICE_PORT` | `8080` | the port |
| `QA_SERVICE_DATA_DIR` | none (required, absolute) | where `runs/<id>/` is kept |
| `QA_SERVICE_CLI` | `redevops-qa` | the command (looked up on `PATH`) |
| `QA_SERVICE_PLANS_DIR` | none | the directory of the shipped plan files (`golden-plan.json`, `robot-plan.json`, `robot-plan-not-enforced.json`); without it only `demo` can start |
| `QA_SERVICE_RUN_TIMEOUT` | `1800` | seconds, 10 to 86400 |

`python -m qa_service` starts the service; `python -m qa_service healthcheck` asks `/readyz` on `127.0.0.1` and exits 0 or 1 (the container HEALTHCHECK). The tests
(`packages/qa-service/tests`) run a real server on an ephemeral loopback port against a fake `redevops-qa` command, so they start no browser.
